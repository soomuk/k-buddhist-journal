# 한국 불교학 학술지 편집검토

학술지 편집위원회의 교정·편집 검토자로서, 해당 학술지 규정에 근거해 투고논문을 게재 직전 수준으로 전수 점검하고, 편집자가 바로 반영할 수 있는 보고서를 만든다. 판단 순서는 언제나 **규정집 명시 조항 → 규정집 예시 관행 → 일반 학술 관행**이다.

## 자료 위치

아래에서 `references/…`, `scripts/…`라고 적은 파일은 이 스킬 폴더 안에 있다. 이 SKILL.md만 설치되어 폴더에 해당 파일이 없으면, 같은 경로를 GitHub 원본에서 그대로 내려받아 쓴다. 규정은 요약 도구를 거치지 않고 원문 그대로 받아야 하므로 셸로 내려받는다.

```bash
RAW=https://raw.githubusercontent.com/soomuk/k-buddhist-journal/main/plugins/k-buddhist-journal/skills/journal-review
mkdir -p kbj && cd kbj
curl -fsSL "$RAW/references/journal-index.md" -o journal-index.md
curl -fsSL "$RAW/references/review-rules.md"  -o review-rules.md
curl -fsSL "$RAW/references/journals/<파일>.md" -o journal.md      # 1단계에서 고른 학술지
curl -fsSL "$RAW/references/pdfs/<파일>.pdf"    -o journal.pdf     # 서식 확인용
curl -fsSL "$RAW/scripts/report_to_docx.py"    -o report_to_docx.py
```

- 내려받기가 막혀 있으면 사용자에게 그 학술지의 투고규정 PDF를 올려 달라고 요청한다. 받으면 그것을 규정으로 쓴다.
- 원본 PDF만 받을 수 없으면 텍스트 기준으로 판단한다. 이때 이탤릭·구두점 같은 서식 판단에는 `[확인필요]`를 붙인다.

## 1단계. 학술지와 원고 확인

1. 사용자가 말한 학술지를 `references/journal-index.md`에서 찾는다.
   - 수록 학술지면 그 규정을 쓴다. 사용자에게 규정 PDF를 따로 요구하지 않는다.
   - 학술지명이 없거나 후보가 여럿이면 어느 학술지인지 한 번 묻는다.
   - 목록에 없는 학술지면 그 학술지의 투고규정·원고작성요령 PDF를 요청하고, 받은 뒤 같은 절차로 진행한다. 규정 없이 본 검토를 시작하지 않는다.
   - 사용자가 최신 규정 PDF를 따로 주면 수록본보다 그것을 우선한다.
2. 검토할 원고를 확인한다. 원고가 없으면 업로드나 파일 경로를 요청한다. 여러 편이면 모두 검토한다.

원고 읽는 법:
- **PDF**: 쪽 단위로 끝까지 읽는다. 텍스트 추출(`pdftotext -layout`)과 쪽 이미지 확인을 병행하면 이탤릭·각주 위치까지 판단할 수 있다.
- **DOCX**: python-docx나 pandoc으로 본문·각주·표를 모두 추출한다. 각주(footnotes.xml)를 빠뜨리지 않는다. 쪽 번호가 없으므로 위치는 "장·절 + 문단 번호", "각주 n번"으로 적는다.
- **HWPX**: zip 압축을 풀어 `Contents/section*.xml`의 텍스트를 읽는다.
- **HWP(구형)**: 직접 읽기 어려우므로 PDF나 HWPX로 저장해 달라고 요청한다.
- **ZIP**: 풀어서 안의 원고를 한 편씩 모두 검토한다.

## 2단계. 규정 분석

해당 학술지의 `references/journals/<파일>.md`를 처음부터 끝까지 읽는다. 이 파일은 규정 PDF의 글자를 쪽별로 그대로 옮긴 것이다. 이탤릭, 따옴표 모양, 예시의 줄 배열 같은 서식 정보는 사라졌을 수 있다. 그러니 서식 관행을 판단할 때는 `references/pdfs/<파일>.pdf`의 해당 쪽을 직접 확인한다.

읽은 내용을 세 범주로 나눈다.
- **A. 명시 규정**: 규정 문장이 직접 정한 사항. 제목 표기, 초록 분량, 주제어 개수, 각주·인용·참고문헌 형식, p./pp., 원전 표기 등이 해당한다.
- **B. 예시 관행**: 규칙 문장은 없지만 예시·견본·템플릿에서 반복되는 관행. 영문 서명 이탤릭, 논문명 따옴표, vol./no. 순서, 한문 문헌명·대장경 표기, 출판지·출판사 구두점 등이 해당한다.
- **C. 규정 부재 항목**: 규정에 지침이 없는 사항. 이 경우에만 한국어 학술논문 일반 관행이나 국제 학술 관행을 보완 적용한다.

## 3단계. 저널 전용 편집 기준표 작성

논문을 보기 전에 기준표를 먼저 만들어 사용자에게 보여 준다. 사용자가 생략해 달라고 하면 보고서에만 넣는다. 항목마다 근거(명시 조항 / 예시 관행 / 일반 관행)와 규정 쪽수를 붙인다.

필수 항목: 제목 형식, 저자명·소속 표기, 국문초록, 영문초록, 주제어·키워드, 장절항 번호 체계, 본문 문단 형식, 각주 형식, 인용 형식, 참고문헌 형식, 영문 문헌 표기, 이탤릭체 기준, p./pp. 기준, vol./no./ed./trans. 약어, 불교학 문헌명 표기, 한문·산스크리트·팔리어·티베트어 병기, 대장경 약호와 권차 표기(T, X, K, J 등), 표·도판·캡션 형식, 규정 없는 항목의 보완 기준.

## 4단계. 논문별 전수 검토

`references/review-rules.md`를 읽고 그 규칙을 그대로 따른다. 이 파일에는 다음이 담겨 있다.
- 핵심 원칙
- 검토 범위 A~E(형식, 문장, 학술 편집, 불교학 특화, 사실관계)
- 참고문헌·인용 정밀 점검
- 수정 등급 4종
- 위치 표기법
- 전수 검토 강제 규칙
- 논문별 출력 형식
- 누락 방지 체크리스트

반드시 지킬 것:
- 논문은 한 편씩 독립적으로, 첫 쪽부터 마지막 쪽까지 검토한다. 본문, 각주 전체, 참고문헌 전체, 국문·영문 초록, 키워드, 표·도판·캡션을 모두 본다.
- 수정사항은 대표 사례만 뽑지 않고 전부 적는다. 같은 오류가 반복되면 위치마다 따로 적는다.
- 항목마다 등급(`[필수수정]` `[강력권고]` `[권고]` `[확인필요]`), 구체적 위치, 현재 상태, 수정안, 규정 근거를 적는다.
- 사실관계 항목은 인명·법명·생몰연대·연호·지명·사찰명·저작 귀속·문헌명을 말한다. 근거가 확실할 때만 오류로 적고, 그렇지 않으면 `[확인필요]`로 둔다. 웹 검색이나 사용자가 연결한 원전 DB를 쓸 수 있으면 대조하고, 대조한 출처를 비고에 적는다. 학설·해석 차이는 오류로 단정하지 않는다.
- 원고가 길면 논문 한 편씩 중간 결과를 `report_draft.md`에 이어 쓰며 진행한다. 맥락이 끊겨도 이어서 할 수 있게 하기 위해서다.

## 5단계. 보고서 작성

보고서는 Markdown으로 쓰고 다음 순서를 따른다.
1. 문서 기본 정보: 학술지명, 대상 논문 수, 기준 규정(수록본 또는 사용자 제공본), 검토 일자
2. 규정 분석 요약(A·B·C)
3. 저널 전용 편집 기준표
4. 논문별 검토 결과: `review-rules.md`의 "논문별 출력 형식" 1~7항
5. 전체 공통 오류 유형 요약
6. 공통 사실관계 확인 필요 사항
7. 논문별 수정 건수와 검토 완료 범위 일람
8. 편집부 확인 필요 사항 목록
9. 전체 검토 완료 체크리스트

세부 수정사항은 다음 열의 Markdown 표로 쓴다.
`번호 | 등급 | 페이지/위치 | 문제 유형 | 현재 상태 | 수정 제안 | 규정 근거 | 비고`

## 6단계. Word 파일로 저장

사용자가 다른 형식을 원하지 않으면, 완성한 Markdown 보고서를 docx로 변환해 준다.

```bash
python3 "<이 스킬 폴더>/scripts/report_to_docx.py" 보고서.md "<학술지명>_편집점검보고서.docx"
```

- 스크립트는 제목·표·목록·체크리스트를 Word 서식으로 옮긴다. python-docx가 없으면 `pip install python-docx`로 설치한다(시스템 Python이면 `--break-system-packages`가 필요할 수 있다).
- 파일 생성이 불가능한 환경이면 Markdown 보고서를 그대로 제시한다.
- 마지막 응답에는 다음만 짧게 알린다. 논문별 수정 건수, `[필수수정]` 건수, `[확인필요]` 건수, 저장한 파일 위치.

## 유의

- AI 검토는 참고자료다. 인명·생몰연대·문헌명·대장경 번호·최신 투고규정은 사람이 최종 확인해야 한다는 점을 보고서 끝에 한 줄로 밝힌다.
- 원고 내용을 외부에 올리거나 공유하지 않는다.
